# МСПиТ ПФО — портал RMRP, сервер №3 «Патрики»

Готовый автономный frontend-портал Министерства социальной политики и труда Патриаршего федерального округа для RMRP GTA5RP, сервер №3 «Патрики».

**Итоговый проект расположен прямо в `I:\rmrp-mspt-site`.** Вложенная папка `mspt-hotline-portal` — исходный пример пользователя; она не участвует в сборке и сохранена без изменений.

## Запуск

Требуется Node.js 22 LTS или новее и npm. В терминале из папки проекта:

```sh
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173`. Если порт занят, Vite покажет другой адрес. Все изображения, шрифты и данные входят в проект. Интернет нужен только для первоначальной установки пакетов. Во время использования портал не обращается к внешним API.

## Production build

```sh
npm run build
npm run preview
```

Готовая статическая сборка — в `dist/`. Просмотр сборки: `http://127.0.0.1:4173`. Двойной щелчок по `index.html` не заменяет локальный запуск Vite: приложение использует ES-модули и маршрутизацию.

Никакой хостинг не подключён. При будущей публикации на выбранном вами сервере настройте возврат `index.html` для маршрутов приложения (`/ministry`, `/submit`, `/track`, `/contacts`, `/staff`). Это стандартный fallback для SPA. Для размещения в подпапке потребуется настроить базовый путь и пути ресурсов.

## Что работает

- Главная горячей линии: один экран с игровым кадром Патриков, лёгким движением фона, подачей и проверкой обращения, ссылкой на Министерство и контактной полосой.
- Переходы между публичными разделами раскрываются круговой волной от эмблемы МСПиТ и поддерживаются масштабированием заголовка; при `prefers-reduced-motion` эффект отключается.
- Большое выездное меню с перспективой, маской, последовательным появлением пунктов и реакцией на фокус/наведение. На телефоне — полноэкранное.
- Отдельные страницы Министерства, руководства, контактов, подачи и проверки обращения.
- Пять шагов формы: сведения, скриншот игрового паспорта, категория, текст, проверка.
- Валидация, drag & drop, preview, обработка неверного формата, ограничение 12 МБ, JPEG/PNG/WebP. Изображение сохраняется локально в уменьшенной копии, без обрезки.
- Номер и шестизначный код доступа, копирование, публичная история и официальный ответ.
- Служебный реестр: поиск (также Ctrl/Cmd+K), статус, тип, дата, исполнитель, пустые результаты.
- Все семь статусов, назначение текущего сотрудника, решение, ответ, закрытие, отклонение с обязательной причиной и внутренние заметки.
- Сохранение после перезагрузки и обновление обращений в других вкладках того же браузера.
- Клавиатурная навигация, фокус, Escape, удержание фокуса в меню/диалоге, ссылка пропуска к контенту и `prefers-reduced-motion`.

## Демонстрация

### Гражданин

1. На главной выберите «Подать обращение».
2. Введите вымышленные ФИО, телефон и почту.
3. Прикрепите тестовое изображение. Для демонстрации можно выбрать `public/assets/ministry/colonnade.png`; проверка содержания паспорта здесь имитируется сотрудником.
4. Выберите жалобу или предложение, введите 20–3000 символов.
5. Проверьте сведения и отправьте. Сохраните выданные номер и код.
6. Нажмите «Проверить статус» — данные подставятся автоматически.

### Сотрудник

В меню или подвале выберите «Для сотрудников» / «Служебный доступ».

- Логин: `admin@mspt.local`
- Пароль: `admin`

Откройте новое обращение и пройдите последовательность:

```text
NEW → ACCEPTED → IN_PROGRESS → DECISION → ANSWERED → CLOSED
  └→ REJECTED
```

**Принято ≠ В производстве.** Принятие только завершает первичную модерацию. Отдельная кнопка «Взять в производство» назначает текущего сотрудника. Нельзя опубликовать ответ до сохранения решения или закрыть дело до ответа. Все события фиксируются. Служебные заметки и назначение исполнителя исключены из публичной проекции данных.

### Готовое обращение для проверки

- Номер: `МСПТ-ПФО-2026-0143`
- Код: `739184`

На странице проверки есть кнопка для подстановки этой пары. Десять исходных обращений охватывают все статусы; остальные коды находятся в `src/data/appeals.js`.

## Архитектура и будущий backend

```text
src/
  components/   — общие элементы, меню, экран успешной отправки
  config/       — редактируемые настройки и контент
  data/         — демонстрационные обращения и руководство
  pages/        — самостоятельные публичные и служебные страницы
  services/     — создание обращения, переходы статусов, публичная проекция, изображение
  styles/       — дизайн-токены, страницы, адаптация и motion
  utils/        — локальное хранилище и форматирование
```

Точки замены:

1. **Authentication:** сейчас `StaffLogin` сверяет локальные `demoCredentials`, а `loadSession/saveSession` хранит только имя, роль и почту в `sessionStorage`. Замените вход и проверку сессии на свой authentication adapter. Демо-пароль нельзя использовать в реальной системе.
2. **Database:** `loadAppeals/saveAppeals` в `src/utils/storage.js` — граница хранилища. Замените их вызовами репозитория/API, добавив асинхронное ожидание в обработчики App. Для записи используйте серверные идентификаторы, версии записей и транзакции.
3. **File Storage:** `src/services/imageService.js` готовит локальную копию скриншота. В реальной системе загружайте исходный файл в приватное хранилище и сохраняйте ссылку/идентификатор вместо Data URL. Доступ к вложению проверяет сервер.
4. **API:** `src/services/appealService.js` содержит чистые функции проверки, создания, переходов, заметок и `publicAppeal`. Их можно использовать как контракт, но все проверки полномочий и этапов нужно повторять на сервере. Публичный endpoint должен возвращать только разрешённые поля.

Ни Firebase, ни Supabase, ни серверные функции, ни API-клиенты сейчас не подключены.

## Что является MOCK и ограничения

Министерство, округ, руководство, адрес, телефон, почта, обращения, даты исходных дел, авторизация, назначение исполнителя и ответы вымышлены. Колоннада создана специально для оформления; аватары условные. Портал не отправляет email, SMS или обращения реальному ведомству. «Предоставить ответ» публикует его только в локальной карточке.

Данные принадлежат конкретному браузеру и origin (схема + адрес + порт). `localhost` и `127.0.0.1` имеют разные хранилища. Другой компьютер или профиль браузера не увидит созданные обращения. Демо-вход не является защитой: все локальные данные можно прочитать через инструменты разработчика. Используйте вымышленные сведения.

Хранилище `localStorage` ограничено браузером. При заполнении приложение показывает ошибку, сохраняет форму и не сообщает об успешной регистрации. Для большого числа вложений в реальной системе нужен File Storage. Многопользовательские транзакции в demo не реализованы.

Ключ обращений: `mspt-portal-appeals-v2`; ключ сессии: `mspt-portal-session-v2`. Чтобы вернуть исходные десять записей, удалите только первый ключ через инструменты разработчика браузера и обновите страницу. Изменения в `data/appeals.js` влияют на начальный набор, а не на уже сохранённую копию.

## Темы и эффекты после UI repair

- `src/config/theme.js`: палитра, цвета поверхностей/текста двух тем, начальный режим, ключ сохранения. Раздел `background` управляет процедурным фоном главной: включение, параллакс, зерно, частицы, скорость орбит, влияние указателя, свечение и интенсивность.
- `src/config/motion.js`: включение движения, интенсивность глубины, длительность страниц/меню/темы/шага, параллакс и фоновые анимации.
- `src/styles/tokens.css`: базовые интервалы, шрифты, семантические переменные и уровни слоёв.
- `src/styles/system.css`: согласованное оформление компонентов, темизация существующих страниц и адаптация.
- `src/styles/footer.css`: независимое оформление подвала; `home.css`: структура главной; `experience.css`: игровая сцена, непрерывная композиция внутренних страниц и мягкое поведение шапки.

Тема сохраняется под ключом `mspt-portal-theme`. Начальный режим — системный. При изменении ключа или начальной политики обновите также короткую начальную инициализацию в `index.html`, которая предотвращает вспышку неверной темы до загрузки приложения.

Готовая сборка при последней проверке запущена на `http://127.0.0.1:4173/`. Полный отчёт о причинах дефектов, изменениях, проверках и ограничениях — `docs/QA.md`. Резервная копия до ремонта — `before-ui-repair.zip`; актуальный архив — `MSPT-PFO-portal-2026-09-26.zip`.
