# МСПиТ ПФО — портал горячей линии

Frontend-портал горячей линии **Министерства социальной политики и труда Патриаршего федерального округа** — ролевого ведомства проекта **RMRP GTA5RP, сервер №3 «Патрики»**.

Портал решает одну задачу: дать жителю округа простой способ связаться с Министерством — подать обращение, отследить его и найти контакты. Служебный контур для сотрудников включён в тот же проект.

Backend пока не подключён: данные живут в `localStorage`, а границы для будущей базы вынесены в отдельные модули (см. «Архитектура и будущий backend»).

---

## Запуск

Нужен Node.js 22 LTS или новее.

```sh
npm install
npm run dev        # http://localhost:5173
```

Production-сборка:

```sh
npm run build      # -> dist/
npm run preview    # http://localhost:4173
```

Проверки:

```sh
npm test                        # модульные тесты сервисов
npm run test:render             # монтирование всех маршрутов в jsdom
npm run format                  # prettier
```

Двойной щелчок по `dist/index.html` не заменяет локальный сервер: приложение использует ES-модули и клиентскую маршрутизацию. Сборка содержит `404.html` — на GitHub Pages и других статических хостингах этого достаточно, чтобы прямые ссылки вида `/ministry` открывались.

Опубликованная версия для GitHub Pages собирается отдельной командой — см. «Публикация на GitHub Pages».

### Демонстрация

**Гражданин.** Подайте обращение, прикрепив любое изображение (подойдёт `public/assets/media/colonnade.jpg`), и сохраните выданные номер и код. На странице проверки есть готовая пара: `МСПТ-ПФО-2026-0143` / `739184`.

**Сотрудник.** Логин `admin@mspt.local`, пароль `admin`.

```text
NEW → ACCEPTED → IN_PROGRESS → DECISION → ANSWERED → CLOSED
  └→ REJECTED
```

«Принято» ≠ «в производстве»: принятие завершает только первичную модерацию, отдельная кнопка назначает исполнителя. Нельзя опубликовать ответ до сохранения решения и закрыть дело до ответа. Отклонение требует причины. Служебные заметки и исполнитель исключены из публичной проекции.

## Публикация на GitHub Pages

Сайт опубликован: **https://rilavion.github.io/test-site-suka/**

Текущая настройка (**Settings → Pages → Build and deployment**):

- Source: `Deploy from a branch`
- Branch: `arena/01a0e713-test-site-suka`, папка: `/docs`

Собранная версия лежит в репозитории, в папке `docs/`. Каждый пуш в эту ветку запускает пересборку Pages автоматически.

**Почему не работало раньше — две причины сразу.** Pages был настроен на корень ветки `main`, которой в репозитории нет (ветка по умолчанию называется `index`). А даже если бы она была — в корне лежит `index.html` для разработки: он подключает `/src/main.jsx`, то есть JSX, который браузер выполнить не может. Нужна собранная версия, и теперь она есть.

### Как обновлять опубликованную версию

```sh
npm run build:pages   # пересобирает docs/
git add docs && git commit -m "Обновление сайта" && git push
```

`npm run build` по-прежнему собирает обычную версию в `dist/` для любого другого хостинга — эта папка в git не хранится.

Если захотите публиковать из ветки по умолчанию, слейте туда изменения и переключите ветку в том же выпадающем списке настроек — папка остаётся `/docs`.

### Что делает сборку пригодной для подкаталога

Pages отдаёт сайт по адресу `/test-site-suka/`, а не из корня домена:

| Файл                      | Роль                                                                           |
| ------------------------- | ------------------------------------------------------------------------------ |
| `vite.config.js`          | `base` берётся из переменной `BASE_PATH`                                       |
| `scripts/build-pages.mjs` | подставляет `/<имя-репозитория>/` и собирает в `docs/`                         |
| `src/utils/basePath.js`   | `asset()` для файлов из `public/`, `toHref()` / `toRoute()` для маршрутизатора |
| плагин `spaFallback`      | кладёт в сборку `404.html` (прямые ссылки вида `/ministry`) и `.nojekyll`      |

Проверить сборку для подкаталога локально:

```sh
npm run build:pages
BASE_PATH=/test-site-suka/ npx vite preview --outDir docs
# http://localhost:4173/test-site-suka/
```

### Вариант через GitHub Actions

Если держать сборку в git не хочется, в `deploy/github-pages.yml` лежит готовый рабочий процесс: он ставит зависимости, прогоняет тесты, собирает портал и публикует его. Добавить его автоматически нельзя — у токена агента нет права записи в `.github/workflows`. Скопируйте файл в `.github/workflows/deploy.yml` (удобно прямо через веб-редактор GitHub) и переключите **Settings → Pages → Source** на `GitHub Actions`. После этого папку `docs/` можно удалить из репозитория.

## Архитектура

```text
src/
  components/
    navigation/Navigation.jsx   — шапка с постоянным меню и выдвижной ящик
    ui/Primitives.jsx           — Mark, Button, StatusPill, Modal, Toast, SplitTitle, useReveal
    ui/Icon.jsx                 — набор линейных иконок
    HeroBackdrop.jsx            — фон главной
    PageIntro.jsx               — общая шапка внутренних страниц
    SiteFooter.jsx              — подвал
    ThemeSwitch.jsx             — переключатель темы с круговой волной
  config/     — редактируемые настройки: контент, темы, движение
  data/       — демонстрационные обращения и руководство
  pages/      — публичные и служебные страницы
  services/   — создание обращения, переходы статусов, публичная проекция, изображение
  styles/     — base · motion · chrome · ui · pages · staff
  utils/      — хранилище, форматирование, базовый путь
```

### Точки подключения backend

1. **Аутентификация.** `StaffLogin` сверяет `demoCredentials`, `loadSession/saveSession` хранят имя, роль и почту в `sessionStorage`. Замените на свой провайдер. Демо-пароль непригоден для эксплуатации.
2. **База данных.** `loadAppeals/saveAppeals` в `src/utils/storage.js` — граница хранилища. Замените вызовами репозитория или API, добавив ожидание в обработчики `App`.
3. **Файлы.** `src/services/imageService.js` готовит уменьшенную локальную копию скриншота. В реальной системе загружайте оригинал в приватное хранилище и сохраняйте ссылку, а доступ проверяйте на сервере.
4. **API.** `src/services/appealService.js` содержит чистые функции валидации, создания, переходов, заметок и `publicAppeal`. Их можно использовать как контракт, но все проверки полномочий нужно повторить на сервере: публичный endpoint должен возвращать только разрешённые поля.

Ни Firebase, ни Supabase, ни серверных функций сейчас не подключено.

## Ограничения демо-версии

Министерство, округ, руководство, адрес, телефон, почта, обращения и ответы вымышлены. Портал не отправляет email, SMS и не связывается с реальным ведомством.

Данные принадлежат конкретному браузеру и origin: `localhost` и `127.0.0.1` имеют разные хранилища, другой компьютер или профиль созданных обращений не увидит. Демо-вход не является защитой — всё локальное содержимое читается через инструменты разработчика. Используйте вымышленные сведения.

Ключи хранилища: `mspt-portal-appeals-v2` (обращения), `mspt-portal-session-v2` (сессия), `mspt-portal-theme` (тема). Чтобы вернуть исходные десять записей, удалите первый ключ и обновите страницу.

Происхождение визуальных материалов — `guide/ASSETS.md`. Отчёт о ремонте интерфейса и ручных проверках — `guide/QA.md`.
